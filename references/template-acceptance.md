# 模板验收参考

按本次模板清单验收，以下常用类型只是参考。具体样式、交互形态和控件范围以用户描述与目标系统证据为准；不要求生成未选类型。

## 文件输出契约

本次清单中的每个项目默认输出一个独立 HTML。文件数量、类型和名称均随本次需求确定。下列仅为常见命名示例：

| 文件名示例 | 可选类型 |
| --- | --- |
| `list.html` | 带筛选和操作的列表 |
| `basic-form.html` | 基础表单 |
| `complex-form.html` | 覆盖多种业务场景的复杂表单 |
| `modal.html` | 基础弹窗 |
| `drawer.html` | 基础抽屉 |
| `customer-detail.html` | 自定义客户详情 |
| `sales-dashboard.html` | 自定义销售看板 |

每个文件可直接打开和独立演示。共享 CSS、JavaScript 或本地资源是允许的。用户未要求合并时，每个清单项分别成页；不要用容器页嵌入其他页面充当独立交付物。一个清单项内部的业务 Tabs、弹窗或抽屉属于该场景的交互，不额外计为独立模板。

若目标使用技能支持的框架与组件库，每个交付页面必须通过本地 `./cdn/` 资源启动相应框架，并实际渲染该场景需要的组件库组件。仅出现资源标签而页面主体仍全部由手写 HTML 控件组成，不通过验收。

## 1. 带筛选和操作的列表

- 有符合目标系统的导航/页头、筛选区、列表工具区、数据区和分页区；列表宽度与内容密度遵守目标页面规则。
- 页面包含两个及以上 Tabs 时，点击每个非默认 Tab 后，当前项样式、`aria-selected` 和对应内容面板必须同步变化；不能把当前项写死，也不能只改变下划线而保持原内容。
- 筛选至少体现文本、枚举、日期或日期范围等不同输入语义，并能查询、重置；可用展开筛选仅在该系统适用时加入。
- 工具区体现主要和次要操作；行操作与状态展示遵守目标组件规范。操作列使用文字链接或系统明确规定的形态，间距、分隔符、显隐、更多菜单与固定位置均可追溯到目标 design.md。仅在有批量业务时加入勾选列与批量操作。
- 数据、空态、加载/错误反馈至少有可检查的呈现方式。排序、分页和操作演示不应出现点击后无响应的假交互。
- 表格宽于容器时处理横向滚动和操作可达性；不要凭空加入另一系统的固定侧栏、卡片壳或分页位置。

## 2. 基础表单

- 使用该系统的表单容器宽度、标签布局、控件尺寸、分组与底部操作规则。
- 覆盖必填、选填、帮助文字、错误提示、禁用和提交中至少几个基本状态；标签与错误信息能关联到控件。
- 提交时执行本地校验并给出可见反馈；取消/重置行为明确。仅展示详情时使用系统相应的只读展示方式。

## 3. 复杂表单

- 用一个连贯业务场景组织多个分区，而不是无关控件的大拼盘。默认至少体现条件字段、可增删的重复项、跨字段约束、日期/数值等专用输入、上传或附件、预览/确认中的数种场景；用户有具体业务需求时按其需求取舍。
- 如果采用步骤、嵌套弹窗、选择列表、远程搜索或实时预览，遵循系统现有组件模式，并使前进/返回、显隐、选择和验证有可见结果。
- 保留各区块数据与错误状态，避免切换条件或步骤时无故丢失输入。无后端时将上传、保存草稿、提交等标为本地演示。
- 长表单的底部操作、滚动和预览区域在目标视口内可用。

## 4. 基础弹窗

- 页面中有触发入口；打开后有遮罩、标题、内容、关闭入口、符合系统顺序的操作按钮。
- 演示短任务或确认场景；确认、取消、关闭、Esc 和遮罩点击行为明确。交互过程中焦点进入弹窗，关闭后回到触发处。
- 内容过高时只滚动内容区，标题与底部操作保持可用；具体宽度、圆角和遮罩来自目标系统。

## 5. 基础抽屉

- 页面中有触发入口；从目标系统规定方向展开，保留原页面上下文。包含标题、可滚动内容、关闭入口和底部操作。
- 演示适合抽屉的快速编辑或详情任务；关闭、取消、提交、Esc 和遮罩点击行为明确，焦点返回触发处。
- 视口较短时头尾保持可用；具体宽度、阴影与层级取自目标系统。

## 自定义模板

- 将用户描述转成信息分区、关键控件、状态和可操作结果；页面结构按场景组织，不强制归入上面的类型。
- 详情页按需求验证信息分组、记录和上下文操作；看板按需求验证指标、筛选联动和数据展示。没有要求的图表或组件不额外添加。
- 自定义交互必须有可观察的结果和验收条件。只有影响页面范围、核心操作或数据呈现的歧义才需要继续询问。

## 通用检查

- 检查正常、悬停、聚焦、选中、禁用、错误等与页面相关的状态。键盘可以到达主要控件，标签、按钮和关闭入口有可理解的名称。
- 按本次清单逐个点击实际存在的交互入口，覆盖相关 Tabs、查询/重置、操作列、更多菜单和浮层等。交互通过的标准是状态与内容确实发生预期变化，不能以“点击时没有控制台报错”代替功能验证。
- CSS 令牌与组件样式应统一，避免在交付页面间出现相互矛盾的尺寸、颜色或布局。外部字体、图片和脚本若不可用，不应导致主要内容空白。
- 所有演示动作应有明确结果；演示数据、模拟提交和未连接的接口应被准确说明。
